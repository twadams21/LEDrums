claim: The host token is the credential that lets a connection bypass the room PIN (pin-gate.ts:195 `isTrustedHost`). It has at least two invariants: minimum entropy, and being safe to place in a URL query and an HTTP request line. Only the first is enforced, and only on one of three paths. `resolveHostToken` (pin-gate.ts:151) accepts any injected `LEDRUMS_HOST_TOKEN` of length >= 32 with no charset check. The Rust shell then interpolates it raw: `format!("POST {path}?hostToken={host_token} HTTP/1.1\r\n…")` (native_midi.rs:111-113) with no percent-encoding, while the Node side reads it back through `new URL(url).searchParams.get('hostToken')` (pin-gate.ts:161), which percent-DECODES. The encode/decode pair is asymmetric: a token containing `+` decodes to a space, `&` truncates it, `%` may decode to a different byte — the desktop MIDI bridge then fails `safeEqual` and silently 401s with no user-visible cause. The same raw value is spliced into a URL fragment at lib.rs:258 (`http://127.0.0.1:{port}/#hostToken={token}`). Compounding it, `HostToken::set` (native_midi.rs:44-54) accepts any `String` with zero validation and is fed from a regex scrape of the sidecar's stdout (`Host token: ([^\s]+)`, sidecar_progress.rs:29) — so the shell's live credential is whatever a log line said, with only "no whitespace" as its guarantee. The Rust newtype `HostToken` looks like the right abstraction but carries no invariant at all.

proposed fix: Give the token a constructor that enforces both invariants in both languages: a `HostToken::parse(&str) -> Option<HostToken>` (Rust) and a `parseHostToken(raw: string): HostToken | null` (TS) that require >= 32 chars AND a strict `[0-9a-f]` (or at minimum URL-unreserved) charset — mint_host_token and generateHostToken already satisfy it. Make `HostToken::set` and `resolveHostToken` reject anything else instead of adopting it, and make the Rust `post` take a `&HostToken` rather than a positional `&str` so it cannot be confused with `path`/`body`. That collapses the encode/decode asymmetry to a non-issue by construction rather than by luck.
