claim: `applyModifierChain` does `const def = tryGetModifier(link.modifierId); if (!def) continue;` and `renderLayer` does `const effect = tryGetEffect(clip.effectId); if (!effect) return;`. Skipping rather than throwing on the render path is the right call — the hot loop must not fault on stale authored data, and the comments say so. What is missing is any record that it happened. A show authored against a build that had `modifier:bloom`, opened on a build that renamed it, produces a layer that renders unmodified (or a clip that renders nothing) with identical UI, identical stats, and nothing in the Monitor stream. The drummer's only symptom is 'this one looks wrong now' with no path from symptom to cause, and the maintainer has no telemetry to detect that a rename shipped without a content migration. The registries are exactly where a rename regression would be caught cheaply.

evidence the author gave:
  [read]  :: packages/core/src/modifiers/chain.ts:47 — `if (!def) continue; // unknown id → skip (never throw on the render path)`. No counter, no callback, no set of seen-unknown ids.
  [read]  :: packages/core/src/engine/engine.ts:230-231 — `const effect = tryGetEffect(clip.effectId); if (!effect) return;` — same silent skip.
  [read]  :: packages/core/src/modifiers/chain.ts:10-11 — the module docstring explicitly documents the skip as intentional, confirming this is a deliberate design with a missing diagnostic rather than an oversight in the guard itself.

proposed fix: Keep the render-path behaviour identical, but add a core-pure, allocation-free 'unresolved id' ledger: a `Set<string>` on the engine (not a module global — determinism must hold) that records each distinct unknown modifier/effect id the first time it is skipped, exposed via a `getUnresolvedIds()` accessor. The server reads it once per stats tick and, on a newly-added id, emits ONE `error` Monitor event ('effect "x" is not registered — this layer renders nothing'), which reaches the UI and the #122 reporter. First-occurrence-only keeps it off the hot path in cost terms.
