  packages/core/src/effects/emitter.ts:74-91 (updateEmissions)

claim: In the spawn loop the order is `if (trig.seq <= state.lastSeq) continue; state.lastSeq = trig.seq; if (state.emissions.length >= MAX_EMISSIONS) break;`. `lastSeq` is committed BEFORE the cap check, so the trigger that trips the cap is permanently marked as consumed without ever producing an emission — the spawn-exactly-once contract in the docstring becomes spawn-at-most-once. Worse, `break` abandons the remaining triggers in `ctx.triggers` for that frame while leaving `lastSeq` at the tripping trigger's seq; the abandoned hits are gone and, since triggers are a per-frame list, will never be revisited. The docstring promises the cap makes a runaway stream 'degrade, never explode', which it does — but nothing counts the degradation, so a fast roll silently loses hits and the effect author has no way to tell a dropped hit from a bug in their spawnData. The same silent-drop applies to the `age > ttlMs` continue on line 82, which also runs after lastSeq is committed.

evidence the author gave:
  [read]  :: packages/core/src/effects/emitter.ts:76-80 — `if (trig.seq <= state.lastSeq) continue; state.lastSeq = trig.seq; if (state.emissions.length >= MAX_EMISSIONS) break;` — the assignment precedes both the cap check and the ttl check.
  [read]  :: packages/core/src/effects/emitter.ts:46 — `export const MAX_EMISSIONS = 64;` with the comment 'a runaway trigger stream degrades, never explodes'; no counter accompanies it.
  [read]  :: packages/core/src/effects/emitter.ts:56-63 — the docstring states 'Each trigger with seq > lastSeq spawns one emission', which the break path violates.

proposed fix: Move `state.lastSeq = trig.seq` to after the cap and ttl checks so a refused trigger is not marked consumed (and, if the loop should still stop, use the max seq actually processed). Add a `droppedAtCap: number` field to `EmitterState`, incremented on the cap path, so hosts can surface 'emissions capped' in stats rather than leaving a fast roll's missing wavefronts unexplained.
