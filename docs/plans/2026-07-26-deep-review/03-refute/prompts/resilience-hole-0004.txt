claim: Neither side implements ping/pong or any staleness check (`grep -rn "ping|pong|heartbeat|isAlive"` across the ws client, main.ts and boot.ts returns zero relevant hits). Liveness is derived purely from the browser's `onclose`, which never fires on a half-open TCP connection — wifi drop, laptop sleep, a dead Cloudflare tunnel. In that state `store.link` stays `'open'`, so every guard of the form `if (this.link !== 'open') return` reads as connected: `hit()` sends a `key` message that `WsClient.send` silently discards (`if (!ws || ws.readyState !== 1) return`, or the `catch {}` two lines below), the local sim is deliberately NOT fired because the server 'owns' resolution, and the drummer hits pads that produce nothing at all with the UI showing a healthy link. The ironic part is that the fix requires no new protocol: the server already pushes a stats frame every 10ms, so a last-frame-received watchdog is a handful of lines. The server side has the mirror problem — it never reaps a dead peer, so the socket stays in the broadcast registry.
