claim: `writeStoredLibrary` and `writeStoredSongLibrary` are void functions with a bare `catch { /* ignore */ }` around `localStorage.setItem` — the docstring calls this best-effort so persistence 'must never throw into the render loop'. That part is right; the hole is that `scheduleSave` then calls `this.saveStatusCtl.saved()` unconditionally on the same tick, so the indicator flips to 'Saved' regardless of whether either write succeeded. QuotaExceededError is the realistic trigger: a show library holding many graphs plus canvas scenes plus the song pool is easily hundreds of KB of JSON, and Safari private mode throws on the first setItem. If the server link is simultaneously down — the exact situation where the local cache is the only copy — the user's work is gone on refresh while the UI has been telling them it is saved. The same unconditional pattern repeats in the `beforeunload` flush (line 1260) and `stopAutosave` (line 1275), which are the last-chance writes.

evidence the author gave:
