claim: Two semantically different identifier kinds live in one `string`-keyed graph record: pad-bound graphs keyed `"${drumId}:${zone}"` (seed.ts:13) and authored graphs keyed `"graph-<n>"` (ids.ts:11-17, GENERATED_ID_RE). A pad graph is a built-in, permanently bound to a physical pad and given an implicit `drum` trigger source; an authored graph is user-created, freely renamable and deletable. Nothing at the type level distinguishes them, so every operation that must behave differently for the two has to re-derive the distinction. The only discriminator in the codebase is an ad-hoc membership set rebuilt from PADS at hydrate.ts:477 (`const padKeys = new Set(pads.map(padKey))`) and threaded as a parameter to hydrate.ts:89 — a set that is correct only as long as the caller remembers to build and pass it. Any other consumer of `store.graphs` (delete, rename, clone, section assignment) sees only `string` and must guess. A pad whose zone were ever named such that its key matched the generated grammar, or a kit rename that changes drumId, silently reclassifies a graph.
