claim: Within one small package, `address: string` denotes two different domain concepts with different invariants. `OscEvent.address` (interfaces.ts:14) is an OSC path — must begin with '/', is case-sensitive, and is the key into the engine's live `oscTable` (voice/engine.ts:357, modulation.ts:92) where an exact-match miss reads as a silent 0. `OscInputStatus.address` (osc.ts:211) is an IPv4 bind interface, defaulting to `'0.0.0.0'`. Both are produced and consumed inside osc.ts, and both are emitted through the same class. The path invariant is enforced only at the parse boundary (osc.ts:81 comment: "OSC 1.0 addresses always begin with '/'"); anywhere else in the system — authored `GraphNode.oscAddress` (types.ts:316), which is only `.trim()`ed at store.svelte.ts:3594 — a user can save an address with no leading slash and the modulation source will read a permanent, silent 0 with no UI feedback. The protocol layer got this right (`OscListenInfo.hosts`, protocol/index.ts:300), which shows the naming collision is confined and cheap to fix.

evidence the author gave:
