## Concrete behavior

1. Mode defaults Manual and ignores all clock events. Persist source mode in project transport if supported cleanly, local selected WebMIDI device id stays machine-local. In MIDI mode choose one browser input OR native desktop destination; explicit selection prevents mixing two clocks or duplicate native/browser forwarding. Do not alter existing note/CC port acceptance. Native destination identified by a fixed source identity at trusted server route, browser device identity carries on event. Source claim/selection must not let arbitrary viewer timing take over.
2. Protocol use e.g. `t:'midiClock', command:'tick'|'start'|'continue'|'stop'|'position', position?` with validated bounded 14-bit position when needed; no fabricated MIDI channel. Include stable source routing if needed. Host receipt clock authoritative, never trust client to set time. No per-tick autosave/full state broadcast/monitor event. Compact clock status piggybacks existing throttled stats or dedicated <=4Hz snapshot. State needs mode/source/status/bpm so UI doesn't promise synchronized when waiting/lost.
3. Pure state: 24 ticks = one quarter-note; Start resets beat0 and playing; Continue resumes position; Stop freezes beat; clocks received while stopped may estimate tempo but must not restart playback. Position pointer units are 16th notes (=quarter beats). Smooth bounded interval history robust to jitter/duplicate/nonpositive intervals; reject implausible outliers, reset interval history after a gap. Support realistic 20..300bpm at least. Seed tempo from manual/current config until enough pulses. Interpolate between received ticks for smooth render if useful, never double count when ticks arrive. Constant stream should not accumulate phase error over bars. Tests with injection, not wall-clock sleeps.
4. No ticks for 1000ms (engineering default) => Lost, freeze external beat and mark not playing; retain last bpm for display. Resume on clock with sensible phase/no giant catchup; no silent auto-switch to manual. Switching Manual uses retained bpm and existing manual transport controls explicitly; tell operator how to recover. Start before first tick can be Waiting/Running but do not claim locked BPM prematurely.
5. Offline simulator must either follow same pure clock snapshot or clearly disable external clock mode when disconnected; prefer shared behavior if it is a small addition. Never claim offline sync if only server supports it. LFO existing absolute-time math may only follow bpm, not transport phase — don't rewrite every effect. Documentation must say MIDI Clock synchronizes transport; effects with seconds/absolute-time remain as authored.
6. UI copy: Timing source [Manual / MIDI Clock], Clock input [Native LEDrums / available WebMIDI inputs], one status and current bpm, concise Ableton instruction to enable Sync on chosen MIDI Output. Expose unavailable WebMIDI honestly in WKWebView and recommend native destination there. Read /make-interfaces-feel-better and repo Impeccable PRODUCT.md; reuse DS.
