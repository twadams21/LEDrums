## What already works — do not rebuild it

- `packages/io/src/osc.ts` implements OSC 1.0 parsing over `dgram` and an `OscInput` bound to
  `OSC_DEFAULT_PORT` (9000), overridable by `OSC_PORT`.
- `apps/server/src/main.ts:691-711` wires it: monitor event, transport-recall, `voiceHost.applyInput`,
  and a `broadcastJson` to clients.
- `oscToEvent` (`apps/server/src/input-router.ts:49`) is deliberately **address-agnostic** — any
  address passes through with the first numeric arg as value, and binding happens downstream in the
  zone-map. This is good design. Do not introduce a fixed address schema.

The routing layer is sound. The defects are all in the **transport and its discoverability**.

## The defects — verify each, then fix

### 1. Bundles are dropped entirely (top suspect)

`parseOsc` bails on the first byte of `#bundle`:

```ts
if (buf.length < 4 || buf[0] === 0x23 /* '#' bundle */) return null;
```

**OSC bundles are extremely common from exactly the senders in scope** — Max/M4L objects and many
hardware/software senders bundle messages with a timetag by default. If Sensory Percussion bundles,
*every single message it sends is silently discarded* and the symptom is indistinguishable from "OSC
is broken".

Implement bundle parsing per OSC 1.0: `#bundle\0`, a 64-bit timetag, then repeating
`int32 size + element`, where each element is itself a message **or a nested bundle** (recurse).
Emit each contained message as its own event. Treat the timetag pragmatically — this is a live
performance path, so deliver immediately rather than scheduling; if you disagree, say why in your
report rather than building a scheduler unasked.

### 2. One unknown type tag discards the whole message

The `default: return null` in the tag loop means a single unsupported tag drops everything,
including the args that parsed fine. Currently handled: `i f s b T F`. Not handled, and all legal:
`d` (float64), `h` (int64), `t` (timetag), `c` (char), `S` (symbol), `r` (rgba), `m` (midi),
`N` (nil), `I` (infinitum), and the `[` `]` array tags.

Handle the ones with an obvious value mapping and **skip-with-correct-width** the rest so the
message still yields its usable args instead of vanishing. Silently returning `null` on a message
you merely didn't understand is the same fail-open silence as defect 3.

### 3. Socket errors are swallowed

```ts
this.socket.on('error', () => {});
```

If port 9000 is already bound (`EADDRINUSE`), OSC is dead and **nothing anywhere says so** — not the
terminal, not the UI. Surface bind failures and socket errors through the monitor path the same way
`apps/server/src/http/native-midi.ts` surfaces its errors (`{ type: 'error', direction: 'local',
source: 'server/osc', … }`), and make a successful bind observable too. `OscInput` lives in
`packages/io`, which must stay IO-interface-pure — expose the error as an event/callback on the
class and do the monitor wiring in `apps/server/src/main.ts`. Do not import server code into
`packages/io`.

### 4. Nothing tells the user where to send OSC

There is no way, from inside the app, to learn the OSC listen address and port. A user configuring
Sensory Percussion or a Max device needs `<this machine's LAN IP>:<oscPort>`. Today they'd have to
read source. Surface it in the UI: the listen host/port, and live evidence that packets are
arriving. Note `InputActivityBadge` (`apps/web/src/lib/ui/InputActivityBadge.svelte`) already exists
for "proof the bound input is actually being heard" — reuse it rather than inventing a second idiom.

**This is a UI change, so the project's non-negotiables apply** (`AGENTS.md`):
compose from the design system (`docs/design-system.html`); anything new and reusable is added to
`apps/web/src/lib/styleguide/` and the file regenerated with `pnpm design-system` **in the same
change**; apply `/make-interfaces-feel-better`; verify with `pnpm ui-shot` against the running app.
Pin `UI_SHOT_BASE` to your dev port and stop any other dev server first — the server binds `PORT`
(default 4321) and ignores `LEDRUMS_WS_PORT`.

## How to prove it

You cannot install Sensory Percussion or Ableton here, and you must not pretend otherwise.
What you *can* do is test the transport against real bytes:

- Unit tests over **hand-constructed byte fixtures** for each case: a plain message, a bundle with
  two messages, a nested bundle, a message carrying `d`/`h`/`N` tags, a truncated/garbage packet.
  Build the fixtures from the OSC 1.0 spec layout, not by round-tripping your own `encodeOsc` —
  a round-trip test only proves you agree with yourself. Extend `encodeOsc` to emit bundles if you
  want round-trip coverage *in addition*, never *instead*.
- An integration test that opens a real `dgram` socket, sends those packets at a live `OscInput` on
  an ephemeral port, and asserts the events that come out — including that a bundle of N messages
  produces N events in order.
- A test that binding a port already in use surfaces an error instead of failing silently.

For each defect, **show the current code failing first** and record that output in the commit body.

## Environment traps — these have cost real time before, do not rediscover them

- **Never run a repo-wide test sweep while Trent is at the machine.** Concurrent `pnpm test` runs
  once spawned 16 vitest processes and wedged the Mac. Prefer `pnpm --filter <pkg> test`.
- **Vitest caps must be set in MIN/MAX pairs**, always all four:
  `VITEST_MIN_THREADS=1 VITEST_MAX_THREADS=2 VITEST_MIN_FORKS=1 VITEST_MAX_FORKS=2`.
  Setting only the MAX makes vitest 2.1.9 throw "minThreads and maxThreads must not conflict" and
  report *no tests, exit 1* — which looks exactly like a broken suite.
- **Verify every push landed**: `git rev-parse --short HEAD` vs `origin/<branch>`. A `git push`
  inside a `| tail -1` pipeline silently did not land once and cost a full CI cycle.
- **`docs/design-system.html` is generated** — on a merge conflict take one side and regenerate with
  `pnpm design-system`. Never hand-resolve it.
- **Running the app**: `infisical run --env=dev -- sh -c 'LEDRUMS_TELEMETRY=on LEDRUMS_ENGINE=voice pnpm dev'`.
- **Secrets**: never print or echo any Infisical value. If one is missing, report the *name* only.
- Killing a stray process: find the specific pid via `lsof -ti :PORT`. Do not use `pkill` patterns.
