What is being replaced, and what already exists
Today decay is a scalar: whole-drum computes velocity · exp(−ageMs / decayMs) and radial-wash does the same — one number picks a fixed exponential. Separately, the app already ships an opt-in ADSR editor (EnvelopeEditor.svelte → EnvelopeEditorView, geometry in envelope-editor-geom.ts): a 480×160 modal you summon per param, with draggable attack / sustain / release handles and per-segment easing. It is a good editor in the wrong place — a modal you visit, not a control you live in.
"Envelope by default" means the scalar row is the envelope: no modal, no opt-in, and the exponential you get today is just the shape it opens with. Each option below is drawn as the param row it would have to fit inside, at the width the Inspector actually has. The dashed grey line in every widget is today's exp(−t/τ) — the shape you have to beat.
Grounding: ADSR stage editors (Omnisphere's simple↔complex switch, FM8's multi-breakpoint curve), gradient stop editors, Lightroom levels. Sources listed in the footer of this file's plan entry.
The constraint that decides this. The Inspector column is ~320px wide. A widget that needs 480px is a modal in disguise — which is what exists already.
The second constraint. Whatever wins has to degrade to a legible thumbnail on the node card (NodeSignalPreview renders envelope faces at 56×32).
A
Two-handle rail — Trent's shape, built
One rail across the hit's life. Two handles: where the value starts and where it ends. Click a handle to select it, then choose that handle's profile. Pick a timed profile and the handle splits in two — a start marker and a stop marker — so you can say "hold full for 40 ms, then leave". Drag handles sideways for time, up/down for level.
Forced from: the brief, verbatim — a 2-handle range slider where the handle owns a profile.
Decayms · env
Wins — still reads as a slider, so it survives at param-row scale and on a node thumbnail. The handle-owns-a-profile idea is genuinely good: the shape is named, not drawn, so two people can talk about "exp out with a 40 ms hold".
Costs — two handles cap you at one transition. Anything with a bump in the middle (attack → peak → fall) is unrepresentable without a third handle, at which point it is option C wearing a hat.
Try — select the left handle, pick Hold. Watch it split.
B
Gradient stops — the envelope as a colour ramp
The life of the hit is a band; stops sit under it like gradient stops. Click the band to add a stop, drag it in time, drag its level. The diamond between two stops biases the interpolation the way a gradient midpoint does — one extra degree of freedom per segment without a second handle. Double-click a stop to remove it.
Forced from: the Photoshop / Figma gradient editor — stops on a rail, midpoints as bias.
Decayms · env
Wins — arbitrary number of stages with no mode switch, and the band is the preview: you read the brightness ramp directly. Midpoint-bias is a cheap, familiar way to get curves without bezier handles.
Costs — level is edited on a second axis that the gradient metaphor does not have, so it fights itself slightly. Easy to end up with 6 stops and no idea which is which.
Try — click the middle of the band to add a stop, then drag the diamond beside it.
C
Mini curve — the existing ADSR editor, shrunk into the row
A 320×96 breakpoint graph inline. Drag points; click empty space to add one; double-click to remove. Select a segment (the line between two points) and give it an easing. This is the shape the codebase already knows how to persist — adsrToPoints already turns a handle shape into a sampled curve.
Forced from: FM8 / After Effects speed graphs — and from the app's own EnvelopeEditorView, miniaturised.
Decayms · env
Wins — expressively complete: anything the engine can sample, you can draw. Shortest path to shipping, because the geometry, the tests and the persistence already exist.
Costs — it is a graph editor in a param row. Hit targets are ~8px, which is fine with a mouse and hostile everywhere else. Also the least "default-feeling" of the four: it looks like a thing you opted into.
Try — click the line between two points to select the segment, then pick an ease.
D
Levels — in-point, gamma, out-point over today's decay
Keeps the exponential and gives you three handles to reshape it, exactly like a Levels dialog: an in-point (when the fall starts), a gamma triangle (how the middle bends), and an out-point (when it reaches zero). No new stages, no drawing — three drags that cover most of what people actually want out of a decay.
Forced from: Lightroom / Photoshop Levels — reshape an existing distribution, don't author a new one.
Decayms · env
Wins — the only option that is honestly default: the existing scalar is a valid state of it (in=0, gamma=1, out=1), so nothing breaks and no migration is needed. Three 1-D drags is the cheapest interaction of the four.
Costs — gamma is an abstraction you have to learn; nobody hums a gamma. Cannot express hold-then-fall, or any rise at all.
Try — drag the middle triangle. That one handle is the whole idea.
