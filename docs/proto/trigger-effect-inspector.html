What "common" actually is — counted, not assumed
Counted across the 45 generators in packages/core/src/effects/impl/ (grep "key: '…'" | sort | uniq -c). Four params carry the library; everything after speed falls off a cliff. The two rows in accent are the proposed common section; the decay/life family is the interesting middle case — recurrent, but spelled four different ways.

saturation49Universal. Same range (0–1), same step (0.01), same meaning, everywhere.
brightness49Universal, and always the last thing you touch before a show.
hue40Plus aliases: baseHue ×4, hueSpread ×4, hueSpan/hueOffset/hueDrift ×2 each, flashHue, warmHue, tipHue. The concept is universal; the key is not.

Also always present, from the node not the generator — Preset, Play mode, Layer, Scope + Target. They are common to every play node regardless of effect, and today they sit above the params. Each option below has to decide whether they join the common section or stay node chrome.
The hue caveat. A common colour block that only binds hue silently skips Confetti Burst (baseHue + hueSpan) and Temp Sweep (warmHue). Either the core normalises the keys, or the common section maps aliases. Option 4 is the only one below that degrades gracefully without that fix.
1
Fixed common header
Colour · Time · Motion pinned at the top and never scrolled away; the effect's own params scroll underneath. The four things you always want stay under the cursor no matter how long the specific list gets.
Forced from: an Ableton device header / a console's fixed strip top.
Wins — muscle memory is absolute: brightness is always in the same pixel. Scroll only ever moves the part that differs.
Costs — the header eats ~150px of a 320px-wide panel before the effect gets a word in. Confetti Burst's 8 params scroll in a 200px window.
2
Tabbed — Common / This effect
Two tabs over one full-height body. Each side gets the whole panel. The tab you were on persists as you switch effects, so "I am tuning colour across four effects" stays a single mode.
Forced from: Photoshop's Layer Style dialog / devtools panes — full-height panes, one at a time.
Wins — most room per param of the four; nothing is ever cramped. Effect-hopping while staying on Common is genuinely fast.
Costs — you cannot see hue and the effect's own hue-spread at the same time, which is exactly when you need both. A tab is a hidden half.
3
Channel strip
A module rail down the left (Colour, Time, Motion, then the effect's own modules), content on the right. The common modules occupy the same rail slots for every effect; only the modules below the divider change. Reads as a device rack, not a form.
Forced from: a mixing-console channel strip — fixed slots, swappable contents.
Wins — the only option where "what changed when I swapped effect" is visible as a shape: the top of the rail is identical, the bottom is not. Scales to a 12-param effect without scrolling the common set.
Costs — 84px of rail off an already-narrow panel; one more click to reach any param. Two-level navigation for what is often 5 controls.
4
Progressive disclosure + filter
One list, no modes. Common params always visible at the top; the effect's own params sit in a fold that remembers whether you left it open. A filter box above narrows both. Degrades perfectly when an effect has odd keys — an unmatched common param simply is not rendered.
Forced from: macOS System Settings / Blender's collapsible panels — one column, disclosure instead of navigation.
Wins — least structure invented, least to learn, and the only one that survives the baseHue/warmHue mess without a core change first. The filter box is the fastest path on a 20-effect night.
Costs — barely a "layout rethink"; it is the current flat list with a fold. Fold state is one more thing to persist per effect (or not — and then it flaps).
